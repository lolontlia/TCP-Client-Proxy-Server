# TCP Client-Proxy-Server Application

## Overview

This project is a small client-server networking application written in C. It uses TCP sockets to send vehicle information through a proxy server and return an estimated vehicle insurance cost.

The client does not communicate directly with the main server. Instead, it sends its request to the proxy. The proxy randomly decides whether to calculate the estimate locally or forward the request to the main server.

This project was created for a programming assignment in CSCE 3530.

## How It Works

The application contains three programs:

- **Client (`client.c`)** – Connects to the proxy on port `5000`, sends a vehicle's make, model, and year, and displays the response.
- **Proxy (`proxy.c`)** – Listens for client requests on port `5000`. It has a 40% chance of handling a request locally and a 60% chance of forwarding it to the main server.
- **Main server (`server.c`)** – Listens on port `6000`, processes requests forwarded by the proxy, and sends an estimate back to the proxy.

All three programs communicate using TCP sockets. The proxy acts as both a server (when receiving client requests) and a client (when forwarding requests to the main server).

## Communication Flow

1. Start the main server.
2. Start the proxy server.
3. Run the client with a vehicle's information.
4. The client sends its request to the proxy.
5. The proxy randomly chooses whether to handle the request locally or forward it.
6. If forwarded, the main server calculates the estimate and returns it to the proxy.
7. The proxy sends the response back to the client.
8. The client displays the estimated cost and identifies whether the response came from `LOCAL` or `MAIN`.

## Technologies Used

- C
- TCP/IP networking
- Socket programming
- `socket()`, `bind()`, `listen()`, `accept()`, `connect()`, `send()`, and `recv()`
- GCC compiler
- Linux/Unix-style terminal

## Requirements

- GCC compiler
- A Linux or macOS environment, or Windows Subsystem for Linux (WSL)
- Three terminal windows

The programs are configured to communicate over `127.0.0.1` (localhost), so they can run on the same computer.

## Compile the Programs

Open a terminal in the project directory and compile each source file:

```bash
gcc client.c -o client
gcc proxy.c -o proxy
gcc server.c -o server
```

## Run the Programs

Keep each program running in its own terminal. Start them in this order.

**Terminal 1 – Main server**

```bash
./server
```

**Terminal 2 – Proxy server**

```bash
./proxy
```

**Terminal 3 – Client**

Run with the default vehicle (2018 Honda Civic):

```bash
./client
```

Or provide a vehicle's make, model, and year:

```bash
./client Toyota Camry 2020
```

The client will display the estimated insurance cost and whether the request was handled by the proxy (`LOCAL`) or the main server (`MAIN`).

## Ports

| Program | Port | Purpose |
|---|---:|---|
| Proxy | 5000 | Receives requests from the client |
| Main server | 6000 | Receives requests forwarded by the proxy |

## Testing

Run the client multiple times to observe both request paths. Because the proxy makes a random decision for each request, the actual results will vary. Over many requests, approximately 40% should be handled locally and 60% should be forwarded to the main server.

The local proxy calculation and main-server calculation intentionally use different formulas, making it easier to identify which program handled a request.

## Notes

- The insurance amounts are example estimates generated by simplified formulas. They are not real insurance quotes.
- This is an educational networking project, not a production insurance application.
- The application is designed for local testing on one computer.
